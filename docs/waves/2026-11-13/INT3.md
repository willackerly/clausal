## Defect 1: MODEL MISMATCH on t2 and lg2, and the "not from the wave" claim

The defect is real, and wider than reported: the same timeout hit four runs of the record in `fe3d81d`, namely c7, c19, t2 and lg2. The MODEL MISMATCH in c38 is the legitimate one that control expects ("the compiled Rust fails, the Lean model holds").

**Cause.** `Spec.negative_controls.contradictory_givens` has a scope no input meets. Its property test rejects 1,000,001 inputs before giving up, which takes 3.6 to 4.0 s on an idle machine against 20 s allowed. When it ran out of time, the input it happened to be evaluating was recorded as "the compiled Rust gives no answer in time". Because the Lean model was "out of scope" there, the run reported MODEL MISMATCH and failed.

**Fix.** That input is now evaluated again, alone, on the compiled Rust; a failing bounded check's input is already replayed the same way.
- If the call answers and the reading holds or does not apply, the input is not reported. The row stays "did not finish" and says the test ran out of time, not the call.
- In every other case (the replay hangs too, errors, or was not made) the finding stands as before.
- If the reading is false there, the input is reported as "fails".
