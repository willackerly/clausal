## How it is computed

Lean evaluates each claim on the operation with its `run` replaced (`Disp.withRun`: same scope, acceptance and Calls value). It does this through both `decide (F.at …)` and `Frames.Check.F`, on two kinds of outcome:
- **The model's own outcome** at each grid point.
- **Substituted outcomes**: every distinct outcome the model gives anywhere on the grid, plus "no answer".

The echo, the book's `flat:` and `coverage:` texts are not read. The two-run table is computed at one pair of different calls for every pair of substituted outcomes, then compared with `Claim.check` at every in-scope related grid pair.

## Q6 fix round: the one defect is real and fixed

**Defect (should-fix): for a sequence, the covers line did not say whose answer "accepted" and "rejected" are.** Confirmed with the reviewer's repro. The display of a claim about a sequence now has a `sequence` line directly after `covers`, and a case that is the model's own outcome is printed with what each call of the sequence did.

The line is computed, not read off the book's sequence text or the name `andThen`:
- Lean runs each operation of the sequence in order at every grid point, each on the state the previous one left, each answer judged by its own operation's `accepted` (for a tied sequence the second input is the tie applied to the first).
- `Disp.seqReport` compares that with the sequence's own `run` and `accepted`: no answer exactly when some call gave none, otherwise accepted exactly when the last call is.
- If that fails at any grid point the line prints NOT SETTLED and `clausal display` stops the run.
