## What the composed theorem says

`release_ascii`: take any policy `p` for which `IdBridge.compile` gives a snapshot `s`, and any request where three kinds of string are ASCII: every string bound to the object, every value the subject holds, and the value of every `read` trigger. Turn the request into identifiers with `IdBridge.intake`. Then `IdSpec.release s` on the identifiers gives the same yes or no as `Spec.release p` on the strings.

`entitled_ascii` says the same for entitlement alone. `listed_ascii` says the listed obligation IDs are the IDs of the obligations the specification lists, in the same order with the same repeats.
