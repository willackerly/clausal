# Supported Rust profile for Charon → Aeneas → Lean

Generated by `scripts/tables.py`; edit `scripts/PROFILE.template.md`. Tools: Charon 0.1.315, Aeneas nightly-2026.11.09-5a392f4, Lean v4.35.0.

**What this is.** Rules for writing Rust that these tools turn into Lean that compiles, today. Each rule has two kinds of backing:

- **Census:** how functions containing the idiom fared in the census (`CENSUS.md`). These are correlations in real code: a function can fail for another reason. Idiom rates ("N of M functions containing … compile") are over nine crates: `cedar-policy-core` is left out of them because nearly all of its functions fail for one tool defect unrelated to their content. Cause-class counts ("class `x`: N functions") are over all ten.
- **Probe:** a tiny function written to isolate the idiom, run through the same pipeline (`probes/profile-probes-0.1.0`, 186 probe functions: 165 translate and compile, 21 do not). A probe shows that this exact form passes or fails, nothing more.

"Translates" below means: Charon extracts it, Aeneas emits a Lean definition with no hole, and Lean compiles it. It does not mean anything has been proved about it.

## Before anything else

1. **Expect the first run on a real crate to produce nothing.** Aeneas aborts the whole crate when one standard-library trait method in use has a signature it cannot translate. In the census this happened on 5 of ten crates; one more stopped in Charon. The triggers seen: any `str` search method (`split`, `find`, `starts_with`, `strip_prefix`, `contains`, `trim_matches`: they all go through `core::str::pattern::Pattern`), and `Iterator::copied`, `Iterator::cloned`, `Iterator::try_fold`. Rules 5 and 6 remove them. Until the tool is fixed, one such call anywhere in the crate costs every function in it.
2. **One pair of mutually recursive trait impls can cost the rest of the crate.** If two types' trait impls call each other through the trait (the `Display` impls of an AST and its children), Aeneas stops analysing functions at that point and every function after it in the crate's declaration order fails with "Internal error". This is 2,210 of the 2,503 counted functions of `cedar-policy-core`. Rule 0 removes it.
3. **Compiling is not the same as usable.** A call to something Aeneas has no model for becomes a Lean `axiom`. The function compiles, but nothing about that call can be proved. Of the 1,469 census functions that compile, 382 have no axiom anywhere beneath them. The profile therefore has two levels: **translates** (rules 0–14) and **fully modelled** (rule 15 and the list of modelled standard-library items at the end).

## The profile in one page

| Write | Avoid | Rule |
|:--|:--|:--|
| recursion over a data type in inherent methods; trait impls that only forward to them | trait impls of two types that call each other through the trait (`write!(f, "{}", child)` both ways) | 0 |
| `while i < n { … i += 1; }`; `for` over a range or slice when the body has no `return` | `return`, `?` or a labelled `break` from inside a nested loop or from a loop inside an `if`/`match` arm | 1, 2 |
| a helper function for the inner loop | `return` from the inner of two loops; `break 'outer` | 2 |
| explicit loops over indices | iterator chains (`map`/`filter`/`collect`/`sum`/`any`/`copied` …) when you need a model, not an axiom | 6 |
| `match` on the `Option`/`Result` | passing a method by name (`.map(Bucket::key_ref)`) | 7 |
| byte slices `&[u8]` and byte comparisons | `str` search methods; `char` in a `match` | 5, 8 |
| integers (fixed point for money) | `f32`/`f64` anywhere in translated code | 9 |
| generics `T: Trait` or an `enum` of the cases | `dyn Trait`, `Box<dyn Error>` | 10 |
| safe indexing `v[i]`, `v.get(i)` | raw pointers, pointer casts, `asm!` | 11 |
| plain `&mut` parameters | closures taking `for<'a>` references; `Cell`/`RefCell`/`Rc` if you need a model | 12, 15 |
| type names that are not `Slice`, `Array`, `Str`, `Result`; parameter names that are not module names | `struct Slice`, `fn f(input: input::Input)` | 13 |
| `if`/`else` chains on signed values | `match` with negative literal patterns | 8 |

## Rules

### 0. Recursion over a data type goes in inherent methods, not through trait impls

- **Evidence (census).** Cause class `mixed_group`: 2214 functions, 26537 lines, all but four of them in `cedar-policy-core`, which has 87 such groups; the first is the eleven `Display` impls of its concrete syntax tree (`parser::fmt`), which format each other.
- **What fails.** `impl Display for Term` writes a `Group` with `{}`, and `impl Display for Group` writes a `Term` with `{}`. Each `fmt` needs the other type's impl as a trait instance, so the two impls and the two functions form one declaration group. Aeneas does not support a group that mixes functions with trait impls, and its function analysis stops at the first one: the functions declared later, related or not, are lost with it.
- **Evidence (probe, a 100-line crate).** With the mutual `Display` impls: 1 of 9 functions compile; the function before the group does, nothing after it. With the recursion moved to inherent methods: 10 of 11.

Before:

```rust
impl fmt::Display for Term {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            Term::Num(n) => write!(f, "{}", n),
            Term::Paren(g) => write!(f, "({})", g),      // needs `Group: Display`
        }
    }
}
impl fmt::Display for Group {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "[{}]", self.inner)                    // needs `Term: Display`
    }
}
```

After:

```rust
impl Term {
    pub fn write_to(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            Term::Num(n) => write!(f, "{}", n),
            Term::Paren(g) => { f.write_str("(")?; g.write_to(f)?; f.write_str(")") }
        }
    }
}
impl Group {
    pub fn write_to(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        f.write_str("[")?; self.inner.write_to(f)?; f.write_str("]")
    }
}
impl fmt::Display for Term  { fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result { self.write_to(f) } }
impl fmt::Display for Group { fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result { self.write_to(f) } }
```

- **A single type that recurses through its own trait impl** (`Display for Expr` writing a boxed `Expr` with `{}`) does not form such a group, but its `fmt` fails in Lean (the generated definition refers to the trait instance before it is defined). Same rewrite.
- **Not tried on cedar itself.** Its 87 groups span many modules; rewriting them is a change to the crate, and each cedar run took too long here to iterate.

### 1. Loops: `while` and `for` both translate; keep exits simple

- **Evidence (census).** Functions containing `while`: 13 of 29 (45%) compile. `for` over an iterator or collection: 16 of 33 (48%). `for` over a range: 5 of 11 (45%). `loop`: 6 of 16 (38%).
- **Evidence (probe).** `for i in 0..n`: translates and compiles. `for x in slice`: translates and compiles. `return` inside a top-level `for`: translates and compiles. `loop { … break value }`: translates and compiles.
- **Why the slice saw `for i in 0..n` fail.** `clausal/translate.sh` runs Aeneas with `-warnings-as-errors`. Every range loop makes Aeneas warn that its Lean model of `core::iter::range::Step` lacks `forward_overflowing` and `backward_overflowing`; under that flag the warning is an error, and any error aborts the crate. The census runs without the flag (checked: the probe crate with the flag added aborts at its first failing function). So: `for` over a range translates, with that warning, when warnings are not errors.
- **Loops are not free.** Every loop becomes a `loop` combinator with a separate body function, and a proof about it still needs an invariant (`clausal/FINDINGS.md`).

### 2. Leave a loop only by `break`, by ending it, or by a `return` when the loop is the last thing in the function body

- **Evidence (census).** Cause class `loop_exit`: 49 functions, 2872 lines. Functions with a `return` inside a loop: 11 of 33 (33%) compile; with `?` inside a loop: 4 of 10 (40%); with nested loops: 0 of 5 (0%).
- **What fails.** Aeneas turns a `return` inside a loop into a `break` plus the code that follows the loop. That only works when the loop is directly in the function body and what follows ends in the function's return. It fails when the loop sits inside an `if` or `match` arm, when the `return` is in the inner of two loops, and for `break 'label`.

Before (**fails** at Aeneas: Early returns inside of loops are not supported yet):

```rust
if !skip {
    let mut i = 0;
    while i < v.len() {
        if v[i] == 0 { return 0; }          // return from a loop inside an `if`
        acc = acc.wrapping_add(v[i]);
        i += 1;
    }
}
acc.wrapping_mul(2)
```

After (translates and compiles):

```rust
let mut hit_zero = false;
if !skip {
    let mut i = 0;
    while i < v.len() {
        if v[i] == 0 { hit_zero = true; break; }
        acc = acc.wrapping_add(v[i]);
        i += 1;
    }
}
if hit_zero { 0 } else { acc.wrapping_mul(2) }
```

- **In real code** (rewrite 7 in `CENSUS.md`, `shlex`'s `next`): a `loop` inside `if let` with a `return` and a nested `while let` became one `while` with a flag plus a helper; +26/−16 lines, tests unchanged.
- **Inside a loop, do not read through a reference to a struct that itself holds references.** Seen once (rewrite 6, `rusty-money`'s `write_digits`): with the exits fixed, Aeneas failed on a loop that read `params.separator_pattern` through `params: &Params<'_>` ("Joining region abstractions containing shared loans whose shared value contains borrows"). Passing the two fields to a helper as plain arguments fixed it. Cause class `loop_join`: 35 functions, 924 lines.

Nested loops: move the inner loop into its own function, which may `return` freely (before: **fails** at Aeneas: Returns inside of nested loops are not supported yet; after: translates and compiles). Labelled break: use a `done` flag in both loop conditions (before: **fails** at Aeneas: Breaks to outer loops are not supported yet; after: translates and compiles).

### 4. Panics are fine

- **Evidence (probe).** `panic!`, `assert!`, `assert_eq!`, `debug_assert!`, `unreachable!`, index out of bounds, arithmetic overflow and division by zero all translate (translates and compiles); each becomes a `fail` in the `Result` monad.
- **Evidence (census).** Functions calling `panic!`: 17 of 23 (74%) compile; `assert!`: 7 of 17 (41%); `debug_assert!`: 25 of 33 (76%).
- **Consequence for specs.** Plain `a + b` panics on overflow in the model whatever the build profile; use `checked_`, `wrapping_` or `saturating_` operations to say which behaviour you mean (all three are modelled).

### 5. Strings: no search methods; take bytes

- **Evidence (census).** Cause class `str_pattern`: 9 functions, 267 lines. Any use aborts the crate (see "Before anything else").
- **Evidence (probe).** `s.starts_with("ab")`: **fails** at Aeneas: uses core::str::pattern::{impl#59}, removed from the input because Aeneas aborts the crate on it. `s.find(':')`: **fails** at Aeneas: uses core::str::pattern::{impl#60}, removed from the input because Aeneas aborts the crate on it. `s.split(',')`: **fails** at Aeneas: uses core::str::pattern::{impl#60}, removed from the input because Aeneas aborts the crate on it.
- **What is modelled for `str`: almost nothing.** `len`, `is_empty`, `as_bytes`, `parse`, `chars`, `==`, `String::push_str`, `to_string` and `format!` all translate, but every one of them is an axiom (translates and compiles (calls with no model, emitted as axioms: `len`)).

Before:

```rust
pub fn find_colon(s: &str) -> Option<usize> { s.find(':') }
```

After (translates and compiles (calls with no model, emitted as axioms: `as_bytes`)); take `&[u8]` instead of `&str` at the boundary to drop the `as_bytes` axiom as well:

```rust
pub fn find_colon(s: &str) -> Option<usize> {
    let b = s.as_bytes();
    let mut i = 0;
    while i < b.len() {
        if b[i] == b':' { return Some(i); }
        i += 1;
    }
    None
}
```

### 6. Iterator chains translate only as axioms; `copied`, `cloned` and `try_fold` abort the crate

- **Evidence (census).** Functions calling `.map(…)`: 21 of 71 (30%) compile; `.iter()`: 19 of 44 (43%); `.collect()`: 6 of 12 (50%); `.into_iter()`: 17 of 29 (59%). Functions containing a closure: 53 of 120 (44%).
- **Evidence (probe).** `v.iter().map(…).collect()`: translates and compiles (calls with no model, emitted as axioms: `default`). `v.iter().any(…)`: translates and compiles (calls with no model, emitted as axioms: `any`). `v.iter().copied().max()`: translates and compiles (calls with no model, emitted as axioms: `default`). `v.iter().sum()`: translates and compiles (calls with no model, emitted as axioms: `default`). `for (i, x) in v.iter().enumerate()`: translates and compiles.
- **Reading.** The chain compiles because every adaptor Aeneas has no model for is declared as an axiom. Nothing can be proved through it. The loop form is fully modelled.

Before:

```rust
pub fn bump(v: &[u32]) -> Vec<u32> { v.iter().map(|x| x.wrapping_add(1)).collect() }
```

After (translates and compiles):

```rust
pub fn bump(v: &[u32]) -> Vec<u32> {
    let mut out = Vec::new();
    let mut i = 0;
    while i < v.len() { out.push(v[i].wrapping_add(1)); i += 1; }
    out
}
```

- **Closures themselves are not the problem.** A closure called directly (translates and compiles), a function taking `impl Fn(u32) -> u32` (translates and compiles), and `Option::map`/`Result::map_err` with a closure over values (translates and compiles) all translate without axioms. A closure that returns a reference into its argument does not (**fails** at Aeneas: Can't end abstraction 4 as it is set as non-endable).

### 7. Do not pass a function or method by name

- **Evidence (census).** Cause class `fn_ptr`: 102 functions, 1376 lines.
- **What fails.** `x.map(Type::method)` makes rustc build a function-item value; Aeneas does not translate one whose signature has a lifetime (any method taking `&self`).

Before (**fails** at Aeneas: Unimplemented):

```rust
pub fn key_of(p: Option<&Pair>) -> Option<&u32> { p.map(Pair::key_ref) }
```

After (translates and compiles); a closure `|q| q.key_ref()` does not help here (**fails** at Aeneas: Can't end abstraction 4 as it is set as non-endable). In real code: rewrites 8 and 9 in `CENSUS.md` (`indexmap`'s `get_index` and `first`, `.map(Bucket::refs)` to a `match`, five changed lines each, compile afterwards, tests unchanged).

```rust
pub fn key_of(p: Option<&Pair>) -> Option<&u32> {
    match p { Some(q) => Some(q.key_ref()), None => None }
}
```

### 8. `match` on integers and enums, not on `char`; no negative literal patterns; no slice patterns

- **Evidence (census).** Cause classes `match_scrutinee`: 10 functions, 199 lines; `lean_match`: 8 functions, 139 lines.
- **Evidence (probe).** `match c { ' ' | '\t' => …}` on a `char`: **fails** at Aeneas: Unsupported switch scrutinee; the same on a `u8` with byte literals: translates and compiles. Ranges of bytes `b'0'..=b'9'`: translates and compiles. `match x { -6 | 1 => … }` on an `i8`: **fails** at Lean: Failed to compile pattern matching: Stuck at remaining variables: [bv✝:(BitVec IScalarTy.I8.numBits)] alternatives: /- [(BitVec.ofFin (Fin.mk 250 .(Na; as an `if` chain: translates and compiles. Slice patterns `[x, .., y]`: **fails** at Aeneas: Inconsistent projection:; with `len()` and indexing: translates and compiles.

Before:

```rust
match c { ' ' | '\t' | '\n' => 0, '#' => 1, _ => 2 }      // c: char
```

After:

```rust
match c { b' ' | b'\t' | b'\n' => 0, b'#' => 1, _ => 2 }   // c: u8
```

### 9. No floating point

- **Evidence (census).** Cause class `float`: 29 functions, 195 lines. Functions with a float literal or type in the body: 0 of 12 (0%) compile.
- **Evidence (probe).** `a + b` on `f64`: **fails** at Aeneas: Invalid inputs for binop. `a < b`: **fails** at Aeneas: Invalid inputs for binop. `x as f64`: **fails** at Aeneas: Unreachable.
- **Worse than a local failure.** A float cast leaves an unfinished definition in the generated file and the rest of the file indented under it; Lean recovers, but the output is no longer something to read or diff.
- **Rewrite.** Integers with an explicit scale (`translates and compiles` for cents as `u64`). Keep float conversions in a separate, untranslated module.

### 10. No trait objects; use generics or an enum

- **Evidence (census).** Cause class `dyn_trait`: 22 functions, 620 lines. Functions with `dyn` in the signature: 0 of 1 (0%) compile.
- **Evidence (probe).** `fn f(s: &dyn Shape)`: **fails** at Aeneas: Function pointers are not supported yet. `Box<dyn Shape>`: **fails** at Aeneas: Function pointers are not supported yet. `?` converting into `Box<dyn Error>`: **fails** at Aeneas: uses external 'alloc::boxed::convert::{core::convert::From<Box<@>, @E>}::from', which Aeneas cannot translate: Dynamic trait types are not supported y.
- **What works.** Traits with default methods, generic functions with bounds (`T: Ord + Copy`, `T: Clone`), associated types, `From`, and derived `Clone`/`PartialEq`/`Ord`/`Default` all translate (translates and compiles). In the census, functions with trait bounds compile less often than average (119 of 211 (56%)), mostly through the other causes in this list.

Before:

```rust
pub fn area(s: &dyn Shape) -> u32 { s.area() }
```

After, generic (translates and compiles) or closed set (translates and compiles):

```rust
pub fn area<S: Shape>(s: &S) -> u32 { s.area() }

pub enum AnyShape { Square(Square), Rect(Rect) }
pub fn area_of(s: &AnyShape) -> u32 {
    match s { AnyShape::Square(q) => q.area(), AnyShape::Rect(r) => r.area() }
}
```

### 11. No raw pointers, pointer casts or inline assembly

- **Evidence (census).** Cause class `raw_ptr`: 35 functions, 601 lines. Functions with an `unsafe` block: 109 of 153 (71%) compile (many `unsafe` blocks only call an `unchecked` function, which becomes an axiom); with a cast to a raw pointer: 0 of 8 (0%).
- **Evidence (probe).** `unsafe { *v.as_ptr() }`: **fails** at Aeneas: Aeneas does not yet support dereferencing raw pointers.; `v[0]`: translates and compiles. `get_unchecked`: translates and compiles.

### 12. Closures that take a borrowed reader: restructure

- **Evidence (census).** Cause class `hrtb`: 12 functions, 430 lines (the `untrusted` crate's whole API is this shape).
- **What fails.** `f: impl for<'b> FnOnce(&'b mut Reader<'a>) -> R`, where the closure's own lifetime `'b` meets the outer `'a`: **fails** at Aeneas: Unimplemented: found an occurrence of a lifetime constraint relating.
- **Rewrite.** Return the reader and let the caller use it (translates and compiles, translates and compiles).

### 13. Names: no type called `Slice`, no parameter named after a module

- **Evidence (census).** Cause class `lean_shadow`: 96 functions, 432 lines. This is a defect in the generated Lean, not in the Rust; the rename is the workaround.
- **What fails.** (a) A type whose last name is an Aeneas builtin (`Slice`, and by the same mechanism `Array`, `Str`, `Result`) and that has a field of that builtin: inside its own declaration Lean reads `Slice` as the type being defined. Everything that uses the type then compiles only with `sorry`. (b) A parameter with the name of a module of the crate: `input.Input.into_value input` is read as a field access on the parameter.
- **Evidence (probe).** `struct Slice<'a> { bytes: &'a [u8] }`: **fails** at Lean: Function expected at Slice but this term has type Sort ?u.2; renamed `ByteSlice`: translates and compiles. `fn f(input: input::Input)`: **fails** at Lean: Invalid field 'Input': The environment does not contain 'profile_probes.input.Input.Input', so it is not possible to project the field 'Input' from an; renamed `inp`: translates and compiles.
- **Rewrite.** Rename. In the rewrite experiment (`CENSUS.md`) five such renames, 2 to 9 changed lines each, all made their function compile with the crates' tests unchanged; the one in `indexmap` took the crate from 378 to 434 compiling functions. If the type is public, keep the old name as a type alias and re-export the new one. Charon also has a `#[charon::rename("…")]` attribute; it was not tried here.

### 14. Formatting (`Display`, `Debug`, `write!`, `format!`)

- **Evidence (census).** Functions with a `Formatter` in the signature: 57 of 93 (61%) compile; functions calling `write!`: 13 of 15 (87%).
- **Evidence (probe).** Simple `Display`/`Debug` impls translate (translates and compiles); `format!`: translates and compiles (calls with no model, emitted as axioms: `format`, `must_use`).
- **Builder-style `Debug` impls fail.** Functions calling `.debug_list()`: 0 of 19 (0%) compile; `.entries(…)`: 0 of 19 (0%); `.field(…)`: 0 of 9 (0%). The builders hold a `&mut Formatter` inside a value that is passed on, a borrow pattern Aeneas does not handle. `#[derive(Debug)]` is not affected: it expands to one call of `debug_struct_fieldN_finish`, and the derived functions of the census crates mostly compile (they are the "written by derives/macros" column of the corpus table in `CENSUS.md`).
- **Reading.** What compiles does so through axioms for the formatting machinery. Treat formatting as outside the verified core, and do not let a `Debug` impl be the reason a module is not translated: keep such impls in a separate module.
